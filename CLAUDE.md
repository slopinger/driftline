# Driftline instructions

Keep this file and README up to date in the same change whenever behavior, tests, deployment or coverage changes. AGENTS.md is a symlink; preserve it.

- Core engine is `web/engine.mjs`, shared by browser and Node CLI, with no network or dependencies.
- Specs/source code are untrusted text. Never insert input through innerHTML, fetch remote refs, execute uploaded code or persist input by default.
- Preserve input bounds and explicitly report limited coverage. Do not claim no findings proves compatibility. Source matches are candidates, never a verified call graph.
- Tests: `node --test test/*.test.mjs` (Node >=20). Browser uses native modules. No npm install/build step.
- Public GitLab under slop, MIT, signed small commits. Scan for secrets before first push.
- Deployment and live URL will be documented here when installed.
- Browser UI: `web/index.html`, `style.css`, `app.mjs`; heavy comparison runs in `worker.mjs`. Example is synthetic `web/demo.json`, regenerated by `node examples/make.mjs`. Input changes invalidate/cancel old reports; file reads have independent revision guards so concurrent selections do not discard each other; exports must only use current report. Use textContent for untrusted content.
- Deployment: `./deploy.sh` (Node on PATH, or Nix shell). Immutable root-owned `/srv/http/driftline/releases/<commit>`, atomic `current` link. Caddy site file `/etc/caddy/conf.d/driftline.freifick.net.caddy`, full validation before reload. Public URL https://driftline.freifick.net. DNS-only A/AAAA; no new listener/service/database. CSP permits only local assets/workers, no analytics.
- Browser QA: `node test/browser.mjs` using external Playwright/Chromium (`PLAYWRIGHT_MODULE`, `CHROMIUM_BIN`, optional `BASE_URL`). No dependency install/build needed for production. Screenshots ignored under artifacts/.

- Every software change must maintain project-owned Nix flake packaging, a committed lockfile,
  development tools and checks. Export a reusable NixOS module where host/service integration
  applies. Verify package builds and relevant flake checks; document supported commands in README.
